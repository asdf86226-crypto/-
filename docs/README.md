# 구매요청 대시보드

개발 · 자재 · 생산 · 품질 팀의 구매요청을 한 곳에서 접수하고 정리하는 단일 파일 대시보드입니다.
별도 설치나 서버 없이 `index.html` 을 브라우저로 열면 바로 동작합니다.

## 실행 (로컬)

```bash
# 파일을 더블클릭하거나, 로컬 서버로 열기
python -m http.server -d docs 8080
# → http://localhost:8080
```

팀원이 링크로 접속하려면 공용 주소가 필요합니다. 이 저장소는 GitHub Pages로 바로 배포됩니다.

**한 번만 켜기** — GitHub 저장소 → **Settings → Pages**
- **Source**: `Deploy from a branch`
- **Branch**: `claude/purchase-request-dashboard-9xcp9x` , 폴더: `/docs` → **Save**

1~2분 뒤 주소가 생성됩니다: `https://asdf86226-crypto.github.io/-/`
이 주소를 팀원에게 공유하면 됩니다(설정 창의 '🔗 팀원 공유용 링크 복사'로 시트 연결까지 담아 전달 가능).

> `docs/.nojekyll` 파일은 Pages가 파일을 그대로 서빙하도록(변환 없이) 하기 위한 것입니다.

## 두 가지 모드

| | 로컬 모드(기본) | 구글 시트 공유 모드 |
|---|---|---|
| 저장 | 내 브라우저(localStorage) | 구글 시트(팀 전체 공유) |
| 입력 | 직접 입력 / 엑셀·CSV 업로드 | **동일**(대시보드에서 직접) |
| 보기 | 나만 | 팀원 모두 실시간 |
| 설정 | 없음 | 대표자 1명이 1회만 |

> 핵심: **팀원은 대시보드에서 평소처럼 입력**하기만 하면 되고, 그 내용이 자동으로 공용 구글 시트에 저장되어
> 모두에게 보입니다. 팀원은 별도 설정이 전혀 없습니다.

## 주요 기능

- **직접 입력**: 요청팀, 품목코드, 품명, 수량, 입고요청일, 기타사항(+요청자)
- **엑셀 파일 업로드**: `.xlsx` 또는 CSV 파일을 선택/드래그하면 자동으로 읽어 일괄 등록
  - 열 순서: `품목코드 · 품명 · 수량 · 입고요청일 · 기타사항` (맨 윗줄 헤더 자동 인식)
  - 엑셀 날짜 셀은 자동으로 `YYYY-MM-DD` 로 변환. 외부 라이브러리 없이 브라우저에서 직접 해석
  - '양식(CSV) 내려받기'로 표준 양식 제공
  - ⚠️ 엑셀은 `717062.0` 을 **숫자로 저장해 `.0` 을 지웁니다**(파일 안에 이미 없어서 복구 불가).
    품목코드 열을 텍스트 서식으로 두거나 CSV로 저장하세요. ERP에 `X` 가 없고 `X.0` 만 있으면
    등록 시 자동으로 맞춰줍니다(양쪽 다 있으면 손대지 않음)
- **실시간 공유**: 구글 시트 연결 시 요청 추가 직후·`⟳ 새로고침` 시점에 동기화
- **ERP 품목 분석**: 품목코드를 넣으면 **현재고 · 월평균 소요 · 소진 예상**을 즉시 표시 (아래 참고)
- **팀별 필터 · 검색 · 정렬**, **요약 집계**, **CSV 내보내기**, **라이트/다크 테마**

## ERP 재고·판매량 연동

구매요청에 품목코드를 입력하면, 왼쪽 **품목 분석** 패널과 목록의 품명 아래에
`재고 1,022 · 월 2,505 · 0.4개월` 형태로 재고와 소요량이 표시됩니다.

필요한 파일과 열은 다음과 같습니다. 회사별로 여러 개 올려도 자동으로 합쳐집니다.

| 파일 | 필요한 열 |
|---|---|
| 재고현황 | `품목코드` `품명 및 규격` **`품목구분`** `재고수량` |
| 판매현황내역 | `일자` `품목코드` `품목명` `수량` (최근 2년치) |
| BOM(소요량)현황 | `생산품목코드` `소모품목코드` `생산수량` `소요량` |

### 방법 A — 자동 갱신 (권장)

**구글 드라이브 폴더에 파일을 덮어쓰기만** 하면 매일 새벽 4시에 Apps Script가 다시 계산해
**팀원 모두의 화면**에 반영합니다.

최초 1회 설정 — 대시보드 **품목 분석 → ⚙ ERP 데이터 → 최초 1회 설정 방법**

1. 구글 시트 → **확장 프로그램 → Apps Script** → 기존 코드를 모두 지우고
   모달의 **📋 Apps Script 새 코드 복사**로 받은 코드를 붙여넣고 저장
2. 함수 목록에서 **`ERP설정`** 선택 → **▷ 실행** (권한 승인 필요 — Drive 접근 권한이 추가됨)
   → 실행 로그에 **`구매요청 ERP 자료` 폴더 주소**가 출력됨
3. **배포 → 배포 관리 → ✏ 편집 → 버전: 새 버전 → 배포** (URL은 그대로라 재공유 불필요)
4. 그 폴더에 ERP 파일을 넣기

동작 방식
- `ERP설정` 이 Drive 폴더 생성 + 매일 04:00 시간 기반 트리거 설치
- `erpRefresh` 가 폴더의 파일을 읽어 계산한 뒤, 결과 JSON을 `erp_blob` 탭에 40,000자씩 나눠 저장
  - `.xlsx` 는 `Utilities.unzip` 으로 직접 풀어 `sheet1.xml` 을 읽습니다(Drive API 변환을 쓰지 않음 —
    v3 `files.copy` 는 `mimeType` 변환을 지원하지 않아 400을 돌려줍니다). 8개 파일 3만여 행에 1초 미만
  - CSV 는 `Utilities.parseCsv`, 구글 시트로 저장된 파일은 그대로 읽습니다
  - 구매요청 스프레드시트가 같은 폴더에 있어도 알아서 건너뜁니다
- 대시보드는 `?erp=meta` 로 **버전만** 먼저 확인하고, 바뀐 경우에만 `?erp=data` 로 본문을 받아
  localStorage에 캐시합니다 (매번 400KB를 받지 않음)
- 모달의 **⟳ 지금 갱신** 은 `erpRefreshOnce` 일회성 트리거를 걸어 5초 뒤 백그라운드로 실행합니다

### 방법 B — 직접 올리기

대시보드 **품목 분석 → ⚙ ERP 데이터 → B** 에서 파일을 끌어다 놓고 **분석 시작**.
브라우저 안에서만 계산하며(**파일은 외부로 전송되지 않음**) 8개 파일 3만여 행이 1초 내외입니다.
결과는 **내 브라우저에만** 남습니다. 팀 전체에 보이게 하려면 **⬇ 결과 파일 저장**으로 받은
`erp-data.json` 을 `docs/` 에 커밋하세요 — 대시보드가 열릴 때 자동으로 읽습니다.

### 소요량 계산 방식

| 품목 유형 | 월평균 소요량 산출 |
|---|---|
| 상품 · 제품 | **실제 판매량** 그대로 |
| 자재 · 반제품 | **BOM 다단 전개** — 이 부품이 들어가는 제품의 판매량 × 소요량 |
| 둘 다 해당 | **두 값을 합산** (직접 판매 + 생산 투입) |

- 전개는 `[원재료]` · `[상품]` 에서 멈춥니다 (원재료 BOM은 합금비가 아니라 모두 `1` 로 들어와 있어 의미가 없음)
- `품목구분` 열이 없는 재고 파일도 동작하지만, 있으면 전개 정확도가 올라갑니다
- **음수 재고**는 마감 전 조정 수치로 보고 `0 (확인필요)` 로 표시합니다
- 소진 예상은 색으로 급한 정도를 표시합니다 — 빨강 `--risk-1` 2개월 미만 / 갈색 `--risk-2` 4개월 미만 /
  초록 `--risk-3` 4개월 이상. 목록 아래 범례와 각 값의 말풍선에 같은 설명이 나옵니다
- 목록의 수량 아래 `+1.0개월` 은 **이번 요청이 몇 개월치인지**(요청 수량 ÷ 월평균 소요)입니다
- BOM이 등록되지 않은 품목은 소요량이 비어 있습니다 — 현재 판매량 기준 커버리지는 25~30% 수준이며,
  BOM이 채워지는 대로 다음 갱신부터 자동 반영됩니다

## 팀 공유 설정 (구글 시트 + Apps Script) — 대표자 1명, 1회만

우측 상단 **`로컬 저장`** 버튼(또는 배너의 `구글 시트 연결`)을 눌러 설정합니다.
**API 키·SQL 없이** 코드를 붙여넣고 배포 URL 하나만 가져오면 됩니다.

**1. 시트 만들고 스크립트 열기**
   - [sheets.new](https://sheets.new) 로 빈 스프레드시트 생성
   - 메뉴 **확장 프로그램 → Apps Script**
   - 기존 코드 지우고, 대시보드 모달에 있는 코드를 붙여넣고 **저장**

**2. 웹앱으로 배포**
   - **배포 → 새 배포** → 유형 **웹 앱**
   - **실행: 나 / 액세스 권한: 모든 사용자** → **배포**
   - 권한 요청 시 본인 계정 승인(**고급 → 이동**)
   - 표시된 **웹 앱 URL**(`…/exec`) 복사

**3. 대시보드에 붙여넣기** → **연결 테스트 → 저장하고 연결**

**4. 팀원 공유** — 설정 창의 **`🔗 팀원 공유용 링크 복사`** 로 링크를 만들어 팀원에게 전달
   - 팀원은 그 링크만 열면 자동 연결됨(설정 불필요)
   - 단, 팀원이 열려면 `index.html` 이 **공용 주소**(GitHub Pages/Netlify 등)에 올라가 있어야 합니다.

## 카카오톡 접수 알림 (선택)

접수가 등록되면 **대표자 본인 카카오톡**으로 알림이 갑니다(카카오 '나에게 보내기').
설정 창의 **카카오톡 접수 알림** 섹션에서 진행합니다(대표자 1회).

1. [developers.kakao.com](https://developers.kakao.com/console/app) → **애플리케이션 추가하기**로 앱 생성
2. **앱 키**의 **REST API 키** 복사
3. **카카오 로그인** 활성화 ON → **Redirect URI**에 대시보드가 알려주는 주소(웹앱 `…/exec`) 등록
4. **카카오 로그인 → 동의항목**에서 **카카오톡 메시지 전송(talk_message)** 사용 설정
5. 대시보드에 REST API 키 입력 → **카카오톡 연결** → 열린 창에서 로그인·동의

> ℹ️ Apps Script 코드에 카카오 기능이 포함되어 있습니다. 코드를 새로 붙여넣었다면
> **배포 → 배포 관리 → 편집 → 새 버전**으로 다시 배포하고, 실행 권한(외부 서비스 연결)을
> 재승인해야 알림이 동작합니다. '나에게 보내기'는 앱을 만든 **본인 계정**으로만 전송됩니다.

### 동작 방식(CORS 우회)

- 읽기: JSONP(`<script>`)로 웹앱 `doGet` 호출 → 목록 수신
- 쓰기: `fetch(..., mode:'no-cors')` 로 `doPost` 에 add/update/remove/clear 전송 후 재조회
- 데이터는 시트의 `requests` 탭에 `id, createdAt, team, code, itemName, qty, dueDate, requester, note` 열로 저장
- 저장 시 해당 행을 **텍스트 서식(`@`)** 으로 고정합니다. 그렇게 하지 않으면 구글 시트가
  `717062.0` 같은 품목코드를 숫자로 인식해 `717062` 로 바꿔버립니다
  (ERP에는 `11058.0`=도금품 / `11058`=미도금품 처럼 **끝자리 `.0` 유무로 구분되는 품목이 532개** 있습니다)

## 데이터 저장 위치

- **로컬 모드(기본)**: 브라우저 localStorage(키 `purchase_requests_v1`)
- **공유 모드**: 연결된 구글 시트(대표자 계정 소유)
- **ERP 분석 결과**: 구글 시트 `erp_blob` 탭(자동 갱신) / localStorage(키 `erp_dataset_v1`,
  버전은 `erp_dataset_ver`) / 선택적으로 `docs/erp-data.json`
  — 방법 B는 원본 ERP 엑셀을 저장하거나 전송하지 않습니다(브라우저 안에서만 읽음).
  방법 A는 원본이 대표자 본인의 구글 드라이브 폴더에 보관됩니다.

> ⚠️ 웹앱을 '모든 사용자' 액세스로 배포하면 **URL을 아는 사람은 누구나** 읽고 쓸 수 있습니다.
> 공유 링크를 사내에서만 배포하세요. 더 엄격히 하려면 배포 액세스를 '조직 내 사용자'로 제한할 수 있습니다.
